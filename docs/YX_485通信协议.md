# YX 设备 RS-485 通信协议

> **来源**:`docs/暑假作业.docx`(OCR 转写,部分字识别有误,具体代号语义由 YX 协议方解释)
> **设备**:YX(机载计算机上一独立的执行单元,基于 32 位单片机)
> **子系统**:电磁拔销器驱动 / 拔销器驱动 / QB 电容充电驱动 / QB 驱动 等
> **状态**:安全状态 / QB 状态(两个独立状态,互不干扰)
> **文档版本**:v0.3(2026-08-03)

---

## 1. 物理层 / 串口参数

| 参数 | 值 |
|---|---|
| 串口设备 | `/dev/ttyS3` |
| 波特率 | 115200 bps |
| 总线 | RS-485 半双工 |
| 收发控制 GPIO | `gpio1-C2`(**高电平发送,低电平接收**) |
| 字节序 | 大端(Big-endian) |

> 485 半双工:同一时刻只能发或收,`gpio1-C2` 控制收发切换。建议发送前 ~1 ms 拉高、整帧发送完成后 ~1 ms 拉低,避免与总线冲突或丢字节。

## 2. 机载计算机 → YX(下行帧,YX 接收)

### 2.1 帧格式

| 字节序号 | 字段 | 值 | 字节数 |
|---|---|---|---|
| 0~1 | 同步码 | `0xEB 0x90` | 2 |
| 2 | 地址码(B) | **机载 `0x01`**,YX `0x02`(本帧填 `0x01`) | 1 |
| 3 | 指令码(C) | 见 §2.2 | 1 |
| 4~5 | 预留(D) | `0x00 0x00` | 2 |
| 6~7 | 预留(E) | `0x00 0x00` | 2 |
| 8~9 | CRC-16/MODBUS(F) | 见 §2.3,对字节 2~7(B、C、D、E) 计算 | 2 |
| | **合计** | | **10 字节** |

### 2.2 指令码表

| 序号 | 命令内容 | 命令解释 | 代码 | 触发条件 |
|---|---|---|---|---|
| 0 | 自检指令 | 默认发送该指令,进行状态自检 | `0x3C` | 周期发送(默认 1 Hz) |
| 1 | 二级保险指令 | **连续收到 10 个**该指令且中间不换其他指令,则解除二级保险 | `0x69` | 手动触发 |
| 2 | QB 电容充电指令 | **连续收到 10 个**该指令且中间不换其他指令,则 QB 电容充电 | `0x87` | 手动触发 |
| 3 | QB 电容放电指令 | **连续收到 3 个**该指令且中间不换其他指令,则 QB 电容放电,恢复三级保险 | `0x1B` | 手动触发 |
| 4 | QB 指令 | **连续收到 10 个**该指令且中间不换其他指令,则进行自毁(条件:一二三级解保 + 进入攻击状态) | `0x4E` | 手动触发 |
| 5 | 自毁指令 | **连续收到 10 个**该指令且中间不换其他指令,则进行自毁(条件:一二三级解保 + 进入攻击状态) | `0xD2` | 手动触发 |

> **"连续 N 个"语义**(2026-08-03 与用户确认):同一指令必须**连续 N 次发送,中间不能夹杂其他指令码**。任何夹杂其他指令码都重置计数。
> 帧号是否连续递增由本节点维护(每帧 +1),YX 端按"同指令连续 N 次"判定。

### 2.3 CRC-16/MODBUS 计算

| 项 | 值 |
|---|---|
| 算法 | CRC-16/MODBUS |
| 多项式 | `0xA001`(反向 `0x8005`) |
| 初始值 | `0xFFFF` |
| 输出 | **小端(低字节在前,高字节在后)** — MODBUS 标准序,与 YX 端对齐 |
| 计算范围 | 字节 2~7(地址码、指令码、D、E 四个字段) |

> 实现参考:`init=0xFFFF; for (b: data) { init ^= b; for (i=0; i<8; ++i) { init = (init & 1) ? (init >> 1) ^ 0xA001 : (init >> 1); } } crc = init` —— 算法输出低字节在前,本协议帧直接按此顺序放入字节 8/9(无需额外翻字节序)。

## 3. YX → 机载计算机(上行帧,YX 发送)

### 3.1 帧格式

| 字节序号 | 字段 | 值 | 字节数 |
|---|---|---|---|
| 0 | 同步头 | `0xAA` | 1 |
| 1 | 同步头 | `0x55` | 1 |
| 2 | 地址码 | `0x02`(YX) | 1 |
| 3 | 状态字 0 | 见 §3.2 | 1 |
| 4~14 | 预留 | `0x00`(当前文档未定义业务字段,保留) | 11 |
| 15 | 校验字节 | 第 1~15 字节累加和的低 8 位 | 1 |
| | **合计** | | **16 字节** |

> **校验**:8 位累加和(2026-08-03 与用户确认,与下行 CRC-16/MODBUS 不同)。范围是字节 0~14 共 15 字节,低 8 位作为字节 15。机载端校验失败时应丢弃整帧、不更新状态。

### 3.2 状态字 0(8 位标志,bit0=LSB)

| 位 | 含义 | 0 | 1 |
|---|---|---|---|
| D0 | 设备是否工作正常 | 故障 | 正常 |
| D1 | 是否自检完成 | 正在自检 | 自检完成 |
| D2 | QB 模式标志(原文"BAOZHA") | 预留 | 预留 |
| D3 | 第一级保险状态 | 未解除 | 解除 |
| D4 | 第二级保险状态 | 未解除 | 解除 |
| D5 | 是否进入攻击状态 | 未进入 | **进入攻击状态(12V 供电且三级解保后自动进入)** |
| D6 | QB 标志 | 未 QB | 已 QB |
| D7 | 自毁标志位 | 未进入自毁模式 | 已进入自毁模式 |

### 3.3 状态机时序(从协议正文提炼,具体状态机由 YX 内部管理)

1. 上电自检 → 报告 D0=1, D1=1(自检完成);
2. 加速度过载触发(YX 内部加速度传感器) → D3=1(一级保险自动解除);
3. 机载下发"二级保险指令"×10 帧连续 → D4=1;
4. 机载下发"QB 电容充电指令"×10 帧连续 → QB 电容开始充电(对应 D6 状态变化);
5. 12V 供电 + 三级解保 → **D5=1 自动进入攻击状态**;
6. 攻击状态下机载下发 QB 指令×10 / 自毁指令×10 → 触发 D7=1 + 实际 QB 动作;
7. QB 电容放电指令×3 → 恢复三级保险。

## 4. ROS 接口(本节点对外)

> 接口基于 §2/§3 协议 + 2026-08-03 与用户确认的设计:

### 4.0 GPIO 收发切换与启动初始化(2026-08-03 补充)

> 节点启动时**主动接管 RS-485 控制 GPIO**(默认拉低进接收模式),不依赖自启动脚本预配置。若自启动脚本/systemd 在节点启动前已用 `gpioset -m signal` 后台占有同一 line,节点会先 kill 该 gpioset 进程再 sysfs 接管,避免同一 line 被两边争抢。

初始化流程(与板子自启动脚本 `set_rs485_receive_mode` 逻辑一致):

1. **清理残留**:若 `kill_stale_gpioset=true` 且发现后台 `gpioset -m signal ... line=N=0` 在跑 → kill 它(防止它占有 line 让 sysfs write 被内核拒);
2. **gpioset 后台占位**(可选):若 `use_gpioset=true` 且板子上有 `gpioset` 命令 → fork `nohup gpioset -m signal -b <chip> <line>=0` 后台持有;但因为节点需要动态切高切低,**占位后立即 kill 让出 line**,实际收发由 sysfs 接管;
3. **sysfs 接管**:`export GPIO N`(幂等) → `echo low > direction` 原子切为输出低电平(老驱动不支持 `low` 时回退 `echo out > direction` + `echo 0 > value`)→ `open value fd` 给后续动态切换;
4. **节点退出**:写低电平 + 关 fd;**不主动重启 gpioset 占位**(留给 systemd 重启脚本决定)。

> **关键不变量**:节点运行期整个生命周期,GPIO 由节点用 sysfs `writeValue(0/1)` 控制。**没有后台 gpioset 占位干扰**。

发送时序(`sendSingleFrame` 内部):

```
gpio writeValue(1)        # 进发送模式
sleep(gpio_settle_ms ms)  # 收发器稳定(默认 2 ms)
serial.write(10 bytes)    # 下行帧
serial.flush()            # 等串口 buffer 全部出去
sleep(gpio_settle_ms ms)  # 收发器稳定(默认 2 ms)
gpio writeValue(0)        # 回接收模式
```

launch 参数映射:

| 参数 | 默认 | 用途 |
|---|---|---|
| `gpio_chip` | "gpiochip1" | libgpiod chip 名(给 `gpioset` 命令用) |
| `gpio_line` | 2 | gpio1_C2 在 chip1 的 line 偏移 |
| `gpio_number` | 98 | sysfs 全局 GPIO 编号 |
| `kill_stale_gpioset` | true | 启动时杀残留 `gpioset -m signal` 进程 |
| `use_gpioset` | false | 启动时尝试后台 `gpioset` 占位(失败回退 sysfs) |
| `pidfile` | /tmp/yx_rs485_gpioset.pid | `gpioset` PID 文件路径 |
| `gpio_settle_ms` | 2 | GPIO 切换前后延迟(收发器稳定) |

### 4.0.1 自检 timer 防护:不打断 SENDING 序列(2026-08-03)

> 协议要求"同指令连续 N 次,中间不能夹杂其他指令"。SENDING 序列(连发 10 帧 0x69/0x87/0x4E/0xD2 或 3 帧 0x1B)进行中,如果 1 Hz 自检 timer 插入 0x3C 帧,YX 端把"连续"计数清零 → 解保/起爆/自毁永远凑不到 N 次。

实现:`selfTestTimerCb` 入口检查 `sending_active_`,true 时**跳过本周期自检**(仅 `ROS_DEBUG_THROTTLE` 一行 log),下个周期 SENDING 结束后再补发。1 Hz 周期下长指令期间少 1~2 次自检对设备无害,自检是周期性的。

### 4.1 节点发布

| Topic | 类型 | 说明 |
|---|---|---|
| `/system/payload_type` | `std_msgs/UInt8` | latched 发布 `7`(= `NHY_PAYLOAD_TYPE_MUNITION`),节点启动时发一次。starling_bridge 的 mavlink_comm 会订阅转发为 MAVLink 42001。 |
| `/yx/status` | `multi_uav_strike/YxStatus`(自建 msg) | 周期发布 YX 上行帧解析结果,字段见 §4.3 |
| `/yx/raw_frame` | `std_msgs/UInt8MultiArray` (16 字节) | 最近一次合法上行帧的原始字节,便于协议调试 |

### 4.2 节点订阅

| Topic | 类型 | 说明 |
|---|---|---|
| `/yx/cmd` | `std_msgs/UInt8` | 收到值 0~5 时按内置"连续 N 次"规则连发对应指令。中间收到其他指令重置当前计数。 |

### 4.2.1 拉烟 Service

| Service | 类型 | 说明 |
|---|---|---|
| `/trigger_smoke` | `std_srvs/Trigger` | 空闲时启动 `0x4E` 连续 10 帧发送。`success=true` 仅表示已接受发送请求，当前不等待拉烟完成反馈。已有其他指令序列时拒绝，不打断原序列。 |

> 拉烟 `0x4E` 已确认完整帧为 `EB 90 01 4E 00 00 00 00 F6 26`。该帧的
> CRC-16/MODBUS 对字节 0~7（包含 `EB 90` 同步头）计算，与本文档旧的
> 通用计算范围不同；当前代码仅对 `0x4E` 按已确认报文处理，其他指令保持旧行为。

### 4.3 `/yx/status` 消息字段(`msg/YxStatus.msg`)

```
std_msgs/Header header

bool device_ok           # D0
bool self_test_done      # D1
bool mode_qb_reserved    # D2 (预留)
bool stage1_released     # D3 一级保险解除
bool stage2_released     # D4 二级保险解除
bool in_attack_state     # D5 进入攻击状态
bool qb_done             # D6 QB 完成
bool self_destruct       # D7 自毁

uint8 raw_status_byte    # 原始状态字 0(便于核对)
bool frame_valid         # 上行帧校验通过
```

## 5. 待确认 / 待补充项

| 项 | 现状 | 处理 |
|---|---|---|
| 上行 11 字节预留的真实含义 | 文档只说 UINT8 预留 | 当前按全 0 处理,如有电压/电流/温度/计数器等业务字段需后续扩展 |
| 默认自检指令发送频率 | 文档说"默认发送" | 当前实现 1 Hz,可在 launch 参数 `~self_test_hz` 调整 |
| GPIO 收发切换的精确时序(切换前后延迟) | 文档无规定 | 当前实现发送前后各 2 ms(`gpio_settle_ms`),可调 |
| GPIO 控制 backend | 板子自启动脚本用 `gpioset -m signal` + sysfs 回退 | 节点启动时主动 kill 残留 gpioset 占位 + sysfs 接管,运行期纯 sysfs(避免与持续持有 line 的 gpioset 冲突) |
| 上行帧是否带 CMD_INV(下行明确无) | 用户已确认不需要 | 已移除 CMD_INV 相关逻辑 |
| CRC-16/MODBUS 字节序 | 已确认 YX 端按 MODBUS 标准序(低字节在前) | 实现:字节 8 = crc & 0xFF,字节 9 = (crc >> 8) & 0xFF |
| 多机载时 YX 是否区分地址 | 文档只给单地址 | 当前实现发 `0x01`,单台 YX 直连,不处理多 YX |
